## ✨ این پروژه چیه؟

NexusNet یک VPS را به مجموعه‌ای از نودهای Tor تبدیل می‌کند که هرکدام روی **یک کشور مشخص** قفل شده‌اند (۵۱ لوکیشن)، بعد همه را خودکار
به پنل شما وصل می‌کند: *اینباند ← اوت‌باند SOCKS ← قانون روتینگ ← هاست*. کاربران از یک ساب‌اسکریپشن می‌توانند 🇩🇪 آلمان، 🇹🇷 ترکیه، 🇳🇱 هلند و … را انتخاب کنند.

| قابلیت | توضیح |
|---|---|
| 🌍 **۵۱ لوکیشن** | پورت SOCKS ثابت و قابل‌پیش‌بینی برای هر کشور |
| 🔌 **۳ پنل** | ثنایی (3X-UI) · پاسارگارد · مرزبان — در مرزبان با هر تعداد نود فقط یک ری‌استارت Xray |
| 🖥 **ریموت VPS** | با SSH روی **نودهای کارگر پاسارگارد** تور نصب می‌کند، داخل کور، اینباند و هاستی که **خودتان انتخاب می‌کنید** |
| 🌐 **Fleet** | مستر + همه‌ی VPSها در یک داشبورد · **Smart Heal** · آپدیت / ری‌استارت همه · مانیتور پس‌زمینه با هشدار |
| 🤖 **بات تلگرام** | هرچه ترمینال دارد — نودها، پنل‌ها، ریموت VPS (افزودن / ویرایش / حذف)، Fleet، بکاپ — از گوشی |
| 📦 **بکاپ و انتقال** | یک فایل ← سرور جدید: موتور، نودها با **همان پورت‌ها**، تنظیمات و اتصال پنل؛ بکاپ روزانه به تلگرام |
| 🛠 **ترمیم خودکار** | نودی که خاموش بماند خودکار ری‌استارت می‌شود (با محدودیت تعداد) |
| 🩺 **Doctor** | علت‌های رایج را پیدا می‌کند: ساعت اشتباه، GeoIP، تداخل پورت، پروکسی باز، مسدود بودن تلگرام |
| 🧹 **حذف امن** | هم سرویس هم کانفیگ پنل را پاک می‌کند — فقط تگ‌های دقیق؛ به اینباندهای خودتان دست نمی‌زند |

## 🚀 نصب

> لینوکس، **root**، اوبونتو / دبیان. پنل باید روی **همان** سرور باشد (نودهای جدا با [ریموت VPS](#remote) پوشش داده می‌شوند).

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/SiNaKeEn/NexusNet-Node/Multi/install.sh)
```

نصب‌کننده یک فایل مستقل است. دفعه‌ی بعد فقط بزنید:

```bash
sudo nxt-node
```

`nexusnet`، `NexusNet` و `panel-tools` هم هنوز کار می‌کنند. ارتقا از نسخه‌ی قدیمی به نودهای شما دست نمی‌زند.

<details>
<summary><b>پیش‌نیازها</b></summary>

| | |
|---|---|
| سیستم‌عامل | Ubuntu 20.04+ / Debian 11+ |
| CPU / RAM | ۲ هسته یا بیشتر · ۴ گیگ یا بیشتر (هر نود یک پروسه‌ی Tor است، حدود ۶۰ مگابایت) |
| پایتون | 3.8+ (خودکار نصب می‌شود) |
| پنل | 3X-UI، پاسارگارد یا مرزبان روی همان سرور |

پینگ نمایش‌داده‌شده یک درخواست کامل **از داخل مدار Tor** است (معمولاً ۰٫۳ تا ۲ ثانیه)، نه پینگ ICMP.
</details>

### خط فرمان (قابل اسکریپت)

```bash
nxt-node                      # منوی تعاملی
nxt-node list [--json]        # نودهای نصب‌شده + وضعیت سرویس
nxt-node add de nl tr         # ساخت نود   (یا: nxt-node add --all)
nxt-node delete tr -y         # حذف نود و کانفیگ پنل آن
nxt-node restart all|de       # ری‌استارت
nxt-node newnym de|all        # مدار جدید Tor / IP خروجی جدید
nxt-node logs de -n 100       # لاگ سرویس یک نود
nxt-node health [de] [--geo] [--json]            # تست از داخل Tor (کد خروج ۱ اگر نودی خراب باشد)
nxt-node fleet [--live] [--heal] [--json]        # مستر + همه‌ی VPSهای ریموت (کد خروج ۱ در صورت مشکل)
nxt-node backup [-o FILE] [--secrets] [--send]   # فایل بکاپ (+ ارسال به تلگرام)
nxt-node restore FILE [-y] [--no-wire]           # بازیابی / انتقال روی همین سرور
nxt-node doctor               # عیب‌یابی
nxt-node bot setup|start|stop|restart|status|logs|test
nxt-node panels               # ابزار پنل‌ها
nxt-node update
```

## 🤖 بات تلگرام

مثل بات‌های ثنایی / پاسارگارد وصلش می‌کنید: **توکن + آیدی ادمین، تمام.**

1. با [@BotFather](https://t.me/BotFather) یک بات بسازید ← **توکن** را کپی کنید.
2. بات را باز کنید و **Start** بزنید. آیدی عددی خودتان را از [@userinfobot](https://t.me/userinfobot) بگیرید.
3. `nxt-node` ← **10** ← **1** ← هر دو را وارد کنید (زبان: فارسی / انگلیسی). پیام تست ارسال و سرویس فعال می‌شود.

اگر تلگرام روی سرور شما مسدود است، در تنظیم اولیه پروکسی اختیاری می‌پرسد (**فقط** برای `api.telegram.org` استفاده می‌شود).

```
   ━━ 🌍 نودها ━━
 [🌍 نودها] [➕ افزودن نود] [🧩 پنل‌ها]
   ━━ 🖥 ریموت VPS ━━

   ━━ 🧰 ابزارها ━━

```

* **همیشه یک پیام** — هر دکمه همان پیام را *ویرایش* می‌کند؛ چت شلوغ نمی‌شود. `/start` منوی قبلی را جایگزین می‌کند.
* **هشدار با دکمه** — هشدار خاموشی دکمه‌های `🔄 DE  🔄 TR …` دارد: نود خراب را مستقیم از همان هشدار ری‌استارت کنید.
* **نودها** — شبکه‌ی وضعیت زنده ← جزئیات، 🏓 پینگ، 🔄 ری‌استارت، 🔁 مدار جدید، 🔗 اتصال به پنل، 🗑 حذف (با تأیید). با **☑️ انتخاب چندتایی** همه را یک‌جا بسازید / ری‌استارت / وصل / حذف کنید.
* **ریموت VPS** — دقیقاً همان گزینه‌های منوی VPS در ترمینال، یک‌به‌یک (پایین‌تر)، شامل **➕ افزودن VPS** و **✏️ ویرایش VPS**.
* **بکاپ** — 📤 ارسال همین حالا، 📅 بکاپ خودکار روزانه، و **فایل `.nxtbak` را برای بات بفرستید تا بازیابی شود**.
* **پنل‌ها** — نودها را به 3X-UI / پاسارگارد / مرزبان وصل کنید. **پسورد پنل هرگز در تلگرام تایپ نمی‌شود** — ورود را یک‌بار با `nxt-node panels` ذخیره کنید.
* **تنظیمات** — ترمیم خودکار، هشدار کندی، بررسی کشور خروجی، گزارش روزانه، فاصله‌ی بررسی، آستانه‌ی هشدار، بی‌صدا، زبان فارسی ⇄ English.

میانبرهای متنی: `/start /status /down /ping [cc] /nodes /node cc /restart cc /newnym cc|all /add [cc] /panels /backup /system /settings /mute 60 /unmute /interval 120 /cancel /help`

هشدار فقط بعد از `fail_threshold` بررسی ناموفق پشت‌سرهم می‌آید. بعد از ویرایش دستی: `nxt-node bot restart`.

## 🖥 ریموت VPS

نودهای کارگر پاسارگارد معمولاً سرور خالی‌اند. نکسوس‌نت با SSH تور را **روی خود نود** نصب می‌کند؛ پس Xray کور به `127.0.0.1` همان نود وصل می‌شود
(بدون باز کردن پورت). مسیر: `nxt-node` ← **21**، یا بات ← 🖥 Remote VPS.

**صفحه‌ی اول:** VPSهای ذخیره‌شده با `آنلاین/کل`، و **افزودن / ویرایش / حذف / تست SSH**. یکی را باز کنید تا منویی هم‌شکل منوی اصلی باز شود — هر گزینه روی همان VPS اجرا می‌شود:

| گزینه‌ی منو | کار |
|---|---|
| **Install / Update NexusNet** | نصب نکسوس‌نت + تور با SSH (اگر هست دوباره نصب می‌کند) |
| **Add Node · Bulk Deploy** | **خودتان انتخاب می‌کنید** کور ← کشورها ← اینباند ← هاست الگو؛ بعد نودها ساخته و به همان کور وصل می‌شوند (یک ذخیره در پنل، آدرس هاست = همان VPS) |
| **List Nodes · Health Check** | لیست نودها؛ Health پینگ و **IP خروجی** هر نود را هم نشان می‌دهد |
| **Edit / Delete Nodes** | حذف روی VPS **و** پاک شدن اینباند / اوت‌باند / رول / هاست از کور پنل |
| **Doctor · Active Ports · System Status** | همان ابزارهای منوی اصلی، روی همان VPS |
| **Restart All / One · New Circuits · Node Logs** | همان چیزی که اسمش می‌گوید |
| **Smart Heal** | نودهای خاموش را ری‌استارت می‌کند، جایی که خروجی اشتباه یا تکراری است مدار جدید می‌گیرد |
| **Select Core · Wire to Panel** | یک VPS می‌تواند چند نود پنل با کورهای متفاوت باشد — **همه** نمایش داده می‌شوند (اول کورهای خود VPS، بعد بقیه)؛ نودهای نصب‌شده را دوباره وصل کنید |
| **Edit VPS · Test SSH · Remove VPS · Delete All Nodes** | مدیریت سرور ذخیره‌شده |

**افزودن VPS** — اگر پاسارگارد وصل باشد یکی از **نودهای پنل** را انتخاب می‌کنید و فقط ورود SSH را می‌دهید. در بات یک ویزارد کوتاه چت است
(*نود ← ورود ← پسورد*)؛ پیام پسورد شما **همان لحظه پاک می‌شود** و فقط روی سرور ذخیره می‌شود (`0600`). کلید SSH هم پشتیبانی می‌شود (کلیدهای پیش‌فرض).

<a id="fleet"></a>

## 🌐 Fleet (ناوگان)

`nxt-node` ← **21** ← **F**، یا بات ← 🖥 Remote VPS ← 🌐 Fleet.

* **داشبورد** — مستر + همه‌ی VPSها در یک صفحه: نودهای آنلاین / کل، میانگین پینگ، مشکلات. **Live Check** از داخل Tor تست می‌کند و چیزی را پیدا می‌کند که
  «سرویس active است» نمی‌بیند: **کشور خروجی اشتباه** و **IP خروجی تکراری**.
* **Smart Heal (ترمیم هوشمند)** — برای یک VPS یا **Heal All**: نودهای خاموش را ری‌استارت می‌کند و جایی که خروجی اشتباه یا تکراری است **مدار جدید** می‌گیرد. اگر مشکلی نباشد به چیزی دست نمی‌زند.
* **آپدیت / ری‌استارت همه‌ی VPSها** — همان کار روی همه به‌صورت موازی (قبلش تأیید می‌گیرد).
* **مانیتور پس‌زمینه** — بات هر ۵ دقیقه همه‌ی VPSها را می‌خواند (یک SSH برای هرکدام) و خبر می‌دهد: در دسترس نیست · نود خاموش · ترمیم شد · دوباره سالم شد.
  نودهای خاموش خودکار ری‌استارت می‌شوند (حداکثر ۳ بار در ساعت برای هر VPS). تنظیمات: کلید `"remote"` در `config.json`.
* **برای cron و اسکریپت** — `nxt-node fleet [--live] [--heal] [--json]` (اگر مشکلی باشد کد خروج ۱).

## 📦 بکاپ و انتقال به VPS جدید

سرور قدیمی از کار افتاد؟ یک فایل همه‌چیز را برمی‌گرداند.

**داخل بکاپ چیست** (`.nxtbak`، JSON، با چک‌سام): لیست نودها **با پورت‌ها**، تنظیمات مانیتور، و اینکه نودها *چطور* به پنل وصل شده بودند
(کدام اینباند، کدام هاست، حالت آدرس). **هیچ پسورد یا توکنی** نیست، مگر خودتان بخواهید (`--secrets`، فقط ترمینال).

```bash
# سرور قدیمی (یا بات تلگرام ← 📦 بکاپ ← 📤 ارسال)
nxt-node backup                      # ← /root/nexusnet-backups/nexusnet-<host>-<date>.nxtbak
nxt-node backup --send               # علاوه بر آن برای ادمین‌های تلگرام می‌فرستد

# سرور «جدید»
bash <(curl -fsSL https://raw.githubusercontent.com/SiNaKeEn/NexusNet-Node/Multi/install.sh)
nxt-node restore nexusnet-....nxtbak
```

`restore` به این ترتیب پیش می‌رود و در هر مرحله می‌گوید چه شد:

1. **موتور** — در صورت نیاز Tor + GeoIP نصب می‌شود
2. **نودها** — با **همان پورت‌های SOCKS / کنترل** دوباره ساخته می‌شوند (نودهای موجود می‌مانند)
3. **تنظیمات** — تنظیمات هشدار / مانیتور (توکن بات فقط اگر فایل شامل اسرار باشد و شما اجازه بدهید)
4. **اتصال پنل** — اینباند و هاست شما را در پنل جدید **با اسم** پیدا می‌کند و همه‌ی نودها را یک‌جا وصل می‌کند
5. **Health check** — صبر می‌کند نودها بالا بیایند و 🟢 / 🔴 گزارش می‌دهد

**بدون ترمینال:** روی سرور جدید بات را راه بیندازید (`nxt-node bot setup`) و **فایل `.nxtbak` را برای بات بفرستید** — طرح بازیابی و دکمه‌ی *Restore now* نشان می‌دهد.
**📅 بکاپ خودکار** را روشن کنید تا هر شب یک فایل تازه در چت شما بنشیند.

> خود پنل (کاربران، اینباندها) باید روی سرور جدید وجود داشته باشد — اول بکاپ خود پنل را برگردانید. پسورد پنل‌ها در فایل نیست:
> اگر پنلی *login needed* گفت، یک‌بار `nxt-node panels` را بزنید.

## 🧩 پنل‌ها

`nxt-node` ← **20**، یا `nxt-node panels`. برای هر نود، نکسوس‌نت در پنل این‌ها را می‌سازد:

`اینباند (کلون از اینباندی که انتخاب می‌کنید، با پورت جدید)` ← `اوت‌باند SOCKS 127.0.0.1:<پورت نود>` ← `قانون روتینگ` ← `هاست`

| پنل | روش | نکته |
|---|---|---|
| **3X-UI / ثنایی** | API پنل + دیتابیس محلی | |
| **پاسارگارد** | API پنل | ورود یک‌بار پرسیده و با `0600` ذخیره می‌شود؛ چندکوره |
| **مرزبان** | API پنل | برای هر تعداد نود یک ری‌استارت Xray؛ تگ‌ها `NexusNet-XX` |

**مرزبان:** از ادمین *sudo* استفاده کنید؛ Xray باید به `127.0.0.1:<پورت نود>` برسد (docker-compose رسمی `network_mode: host` دارد و کار می‌کند)؛
اول روی اینباندی که می‌خواهید کلون شود حداقل یک هاست بسازید؛ کاربرانی که لیست اینباند مشخص دارند باید اینباندهای جدید `NexusNet-XX` را هم مجاز داشته باشند.

**قوانین ایمنی (همه‌ی پنل‌ها):** اینباندهای غیر از نکسوس‌نت **هرگز** حذف یا تغییر نمی‌کنند — اگر پورت دلخواه اشغال باشد نود رد می‌شود
(3X-UI / پاسارگارد) یا به پورت آزاد بعدی می‌رود (مرزبان)؛ حذف فقط با **تگ دقیق** انجام می‌شود.

---

## 🔒 امنیت

* پورت‌های SOCKS تور پیش‌فرض روی **127.0.0.1** هستند. پنل ریموت؟ `NXT_SOCKS_BIND=0.0.0.0` **و فایروال**. `nxt-node doctor` درباره‌ی پورت‌های باز هشدار می‌دهد.
* توکن بات، ورود پنل‌ها و ورود SSH VPSها در `/etc/nexusnet/` هستند (پوشه `0700`، فایل‌ها `0600`). هرگز آن‌ها را در issue نگذارید.
* بات فقط به آیدی‌های ادمین جواب می‌دهد؛ غریبه‌ها یک «دسترسی ندارید» می‌گیرند.
* پسوردهایی که در بات تایپ می‌شوند (فقط SSH مربوط به VPS) همان لحظه از چت پاک می‌شوند؛ کلید SSH بهتر است. پسورد پنل‌ها هرگز در تلگرام تایپ نمی‌شود.
* بکاپ‌هایی که از تلگرام می‌روند توکن یا پسورد ندارند؛ فایل بازیابی قبل از هر کاری از نظر حجم، چک‌سام و ساختار بررسی می‌شود.
* حذف و ری‌استارت همه همیشه تأیید می‌گیرند (`nxt-node delete` هم، مگر با `-y`).

## 🛟 عیب‌یابی

| نشانه | کار |
|---|---|
| نودها هیچ‌وقت آنلاین نمی‌شوند | `nxt-node doctor` (ساعت، GeoIP، RAM) · `nxt-node logs de` |
| بات جواب نمی‌دهد | `nxt-node bot logs` · `nxt-node doctor` (تلگرام در دسترس است؟) · پروکسی را در *تنظیمات هشدار* بگذارید |
| تنظیم اولیه می‌گوید «chat not found» | بات را باز کنید و **Start** بزنید، بعد *Send test message* |
| پنلی در بات «login needed» است | یک‌بار `nxt-node panels` را در ترمینال سرور بزنید |
| یک VPS ریموت *check failed* نشان می‌دهد | بازش کنید ← **Install / Update NexusNet** (روی آن VPS `nxt-node` قدیمی است) |
