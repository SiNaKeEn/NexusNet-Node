# NexusNet Node

**یک سرور، چندین کشور خروجی.** مدیریت نودهای Tor چندلوکیشن با پشتیبانی کامل از
**ثنایی (3X-UI) · پاسارگارد · مرزبان** و **بات تلگرام برای پایش سلامت نودها**.

</div>

<div dir="rtl">

## NexusNet چیست؟

NexusNet یک VPS را به مجموعه‌ای از نودهای Tor تبدیل می‌کند که هرکدام روی **یک کشور مشخص** قفل شده‌اند (۵۱ لوکیشن)،
و آن‌ها را خودکار به پنل شما وصل می‌کند: اینباند، اوت‌باند SOCKS، قانون روتینگ و هاست.
کاربران از یک ساب‌اسکریپشن می‌توانند «🇩🇪 آلمان»، «🇹🇷 ترکیه»، «🇳🇱 هلند» و … را انتخاب کنند.

| قابلیت | توضیح |
|---|---|
| 🌍 ۵۱ لوکیشن | پورت SOCKS ثابت و قابل‌پیش‌بینی برای هر کشور |
| 🔌 سه پنل | ثنایی · پاسارگارد · **مرزبان** (جدید، کاملاً خودکار) |
| 🤖 بات تلگرام | پینگ همه‌ی نودها، هشدار فوری قطعی، ریستارت با یک کلیک |
| 🛠 ریستارت خودکار | نودی که خاموش بماند خودکار ریستارت می‌شود (با محدودیت تعداد) |
| 🔄 NEWNYM | با هر ریستارت مدار/آی‌پی خروجی جدید |
| 🧹 حذف تمیز | هم سرویس را پاک می‌کند هم تنظیمات پنل را (فقط با تطبیق دقیق تگ) |
| 💾 بکاپ | لیست نودها و پورت‌ها در یک فایل |

### پیش‌نیازها
Ubuntu 20.04+ یا Debian 11+ · حداقل ۲ هسته و ۴ گیگ رم · دسترسی root · پنل روی **همان سرور** نصب باشد.

> **درباره‌ی پینگ:** عدد پینگ یک درخواست کامل از داخل مدار Tor است (معمولاً ۰٫۳ تا ۲ ثانیه)، نه پینگ ICMP.

## 🤖 بات تلگرام و مانیتورینگ

مثل بات پنل‌های ثنایی و پاسارگارد: **توکن + آیدی ادمین و تمام.**

۱. در [@BotFather](https://t.me/BotFather) یک بات بسازید و توکن را بردارید.
۲. وارد بات خودتان شوید و **Start** بزنید. آیدی عددی خودتان را از [@userinfobot](https://t.me/userinfobot) بگیرید.
۳. در ترمینال: `nxt-node` ← گزینه‌ی **۱۷** ← **۱** و توکن و آیدی را وارد کنید. پیام تست فرستاده می‌شود و سرویس فعال می‌شود.

**کارهایی که انجام می‌دهد**

* هر ۲ دقیقه (قابل تنظیم) همه‌ی نودها را چک می‌کند: سرویس systemd ← پورت SOCKS ← bootstrap تور ← درخواست واقعی از داخل نود (همان *پینگ*) ← (اختیاری) تطبیق کشور خروجی.
* هشدار **گروهی** (یک پیام، نه ۴۰ پیام) بعد از چند چک ناموفق پشت‌سر‌هم، و پیام **بازگشت** همراه با مدت قطعی.
* اگر خودِ سرور اینترنت نداشته باشد همین را می‌گوید تا دنبال ۵۱ نود «خراب» نگردید.
* **ریستارت خودکار** نود خاموش (پیش‌فرض حداکثر ۳ بار در ساعت برای هر نود).
* یادآوری نودهای هنوز-خاموش، هشدار نود کند (اختیاری)، گزارش روزانه (اختیاری).

**دستورهای بات** (فقط ادمین‌ها)

| دستور | کار |
|---|---|
| `/status` | وضعیت و پینگ همه‌ی نودها |
| `/down` | فقط نودهای مشکل‌دار + دلیل |
| `/ping [cc]` | بررسی زنده‌ی همه یا یک نود |
| `/node de` | جزئیات: سرویس، پورت، درصد bootstrap، آی‌پی خروجی، خطا |
| `/restart [cc]` · `/restart_all` | ریستارت (برای «همه» تأیید می‌گیرد) |
| `/newnym cc\|all` | مدار جدید Tor |
| `/system` · `/ip` | آپتایم، لود، رم، دیسک · آی‌پی سرور |
| `/settings` · `/mute 60` · `/unmute` · `/interval 120` | کنترل هشدارها |

زبان پیام‌ها هنگام راه‌اندازی انتخاب می‌شود (فارسی یا English). جزئیات: [docs/TELEGRAM_BOT.md](docs/TELEGRAM_BOT.md)

## پنل‌ها

`nxt-node` ← **۱۶** (یا `nxt-node panels`). برای هر نود در پنل ساخته می‌شود:

اینباند (کلون از اینباندی که انتخاب می‌کنید، با پورت جدید) ← اوت‌باند SOCKS به `127.0.0.1:<پورت نود>` ← قانون روتینگ ← هاست

| پنل | روش | نکته |
|---|---|---|
| ثنایی (3X-UI) | API پنل + دیتابیس محلی | |
| پاسارگارد | API پنل | یوزر/پسورد یک بار پرسیده و با دسترسی `0600` ذخیره می‌شود |
| مرزبان | API پنل | **برای هر تعداد نود فقط یک ریستارت Xray**؛ تگ‌ها `NexusNet-XX`؛ [docs/MARZBAN.md](docs/MARZBAN.md) |

قاعده‌ی ایمنی: اینباندهای شخصی شما **هرگز** حذف یا تغییر نمی‌کنند؛ اگر پورت اشغال باشد آن نود رد می‌شود
(ثنایی/پاسارگارد) یا به پورت آزاد بعدی می‌رود (مرزبان). حذف فقط با تطبیق دقیق تگ انجام می‌شود.

## امنیت

* پورت‌های SOCKS تور حالا به‌صورت پیش‌فرض فقط روی **127.0.0.1** گوش می‌دهند. اگر پنل شما روی سرور دیگری است:
  قبل از ساخت نودها `NXT_SOCKS_BIND=0.0.0.0` را ست کنید **و حتماً فایروال بگذارید**.
* توکن بات و پسورد پنل‌ها در `/etc/nexusnet/` (دسترسی `0700`/`0600`) ذخیره می‌شود.
* بات فقط به آیدی‌های ادمین جواب می‌دهد.
